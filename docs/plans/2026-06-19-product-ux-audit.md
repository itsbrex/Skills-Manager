## 审查方法论

- **视角**：仅从终端用户角度，不涉及代码实现细节
- **维度**：首次使用门槛 / 核心操作可见性 / 错误反馈 / 边界场景 / 一致性 / 效率
- **严重程度**：
  - 🔴 高：影响首次使用或核心流程，必须优先修
  - 🟡 中：影响效率或一致性，次优先
  - 🟢 低：体验细节，迭代优化
- **每个问题包含**：现象 / 影响 / 改进建议 / 验收标准 / 关联文件

## 模块一：Welcome 引导流程

### W-05 🔴 底部未显示当前版本号

- **现象**：Welcome 流程底部展示 "Skills Manager" 字样，但未附带当前应用版本号。
- **影响**：用户在引导阶段无法确认正在使用的版本，出现问题反馈时缺少版本信息；与设置页"关于"部分的版本信息不一致体验。
- **改进建议**：底部 "Skills Manager" 文案后追加版本号（如 `Skills Manager v2.1.0`），版本号读取自 `package.json` / `tauri.conf.json`，保持与关于页一致。
- **验收标准**：
  - [x] Welcome 每一步底部显示 "Skills Manager v{版本号}"
  - [x] 版本号与应用实际版本一致
  - [x] 版本升级后自动更新
- **关联文件**：`src/pages/Welcome.tsx`、`src/components/welcome/*.tsx`

### W-02 🔴 失败用 alert()，部分失败静默处理

- **现象**：Welcome 流程中设置保存失败用浏览器原生 `alert()` 提示；某些失败场景直接静默吞掉错误。
- **影响**：原生 alert 在桌面应用里观感突兀且阻塞主线程；静默失败让用户以为成功，后续操作才暴露问题。
- **改进建议**：统一使用应用内 Toast/通知组件；所有失败路径必须有用户可见反馈。
- **验收标准**：
  - [x] 全流程不再出现 `alert()` / `confirm()` 原生弹窗
  - [x] 所有失败路径有 Toast 提示，包含错误原因
  - [x] 静默 catch 改为可见反馈
- **关联文件**：`src/components/welcome/*.tsx`

### W-03 🟢 工具检测后无引导启用

- **现象**：[ToolDetectionStep.tsx](file:///Users/yjw/code/projects/skills-manager/src/components/welcome/ToolDetectionStep.tsx) 检测到工具后只展示状态，没有引导用户去启用/配置。
- **影响**：用户检测完工具却不知道下一步该做什么，可能直接跳过，导致 Skills 不会同步到这些工具。
- **改进建议**：检测到工具后提供"立即配置"按钮直接进入启用流程，或在下一步自动应用推荐配置。
- **验收标准**：
  - [x] 检测到工具后有明确的"启用同步"入口
  - [x] 用户可在 Welcome 内完成工具启用
- **关联文件**：`src/components/welcome/ToolDetectionStep.tsx`

### W-04 🔴 导入 Skills 默认全选无预览

- **现象**：[ImportSkillsStep.tsx](file:///Users/yjw/code/projects/skills-manager/src/components/welcome/ImportSkillsStep.tsx) 扫描已有 Skills 时默认全选。
- **影响**：用户可能导入大量不需要的技能造成混乱；且无技能预览/说明，用户无法判断要不要导入。
- **改进建议**：默认不选或只选推荐项；每个技能提供简短描述/标签帮助判断。
- **验收标准**：
  - [x] 默认不全选（或只选标记为推荐的）
  - [x] 每个技能项展示描述/标签
  - [x] 提供全选/反选快捷操作
- **关联文件**：`src/components/welcome/ImportSkillsStep.tsx`

### W-06 🟢 工具检测/导入 Skills 页面长列表滚动逻辑不统一

- **现象**：[ToolDetectionStep.tsx](file:///Users/yjw/code/projects/skills-manager/src/components/welcome/ToolDetectionStep.tsx) 和 [ImportSkillsStep.tsx](file:///Users/yjw/code/projects/skills-manager/src/components/welcome/ImportSkillsStep.tsx) 在工具或已有 Skills 数量较多时都会出现长列表，但两页面的滚动容器、滚动条样式、上下翻页交互不一致。
- **影响**：用户在 Welcome 流程中翻看长列表时体验割裂，滚动行为不可预期；某一步可能整页滚动导致底部按钮被顶出视口，另一步可能列表内滚动但区域过小。
- **改进建议**：统一两步的滚动方案——列表区域使用固定高度 + 内部滚动，底部"上一步/下一步"按钮始终固定在视口底部；滚动条样式统一；支持鼠标滚轮和键盘上下方向键导航。
- **验收标准**：
  - [x] 两步骤列表区域滚动行为一致（列表内滚动，非整页滚动）
  - [x] 底部导航按钮始终可见，不被列表顶出视口
  - [x] 滚动条样式统一
  - [x] 支持键盘方向键导航列表项
  - [ ] 长列表（50+ 项）下性能流畅
- **关联文件**：`src/components/welcome/ToolDetectionStep.tsx`、`src/components/welcome/ImportSkillsStep.tsx`

## 模块二：Skills 管理页面

### S-01 🔴 头部按钮过多，信息过载

- **现象**：[Skills.tsx](file:///Users/yjw/code/projects/skills-manager/src/pages/Skills.tsx) 头部塞了：刷新、标签过滤、搜索、批量翻译、批量管理/退出、批量配置工具、项目绑定、新建 Skill 等 8+ 个操作。
- **影响**：用户一眼看不出主操作是什么；小屏幕下按钮挤压变形；新手不知道从哪开始。
- **改进建议**：区分主次操作——"新建 Skill"作为主按钮突出；批量类操作收进"更多"菜单；标签过滤可移到侧边或折叠区。
- **验收标准**：
  - [x] 头部主操作（新建 Skill）视觉突出
  - [x] 批量类操作收纳到次级菜单
  - [x] 1280px 宽度下头部不换行不挤压
  - [x] 所有操作仍可通过 1-2 次点击触达
- **关联文件**：`src/pages/Skills.tsx`

### S-02 🟡 批量翻译与批量管理模式逻辑不一致

- **现象**：批量翻译有自己的选择态，批量管理又是另一套选择态，两者不互通。
- **影响**：用户选了一批 Skill 想既翻译又配置工具，需要选两次，认知负担大。
- **改进建议**：统一批量选择态，进入"批量模式"后可对选中项执行多种操作（翻译、配置工具、删除等）。
- **验收标准**：
  - [x] 统一的批量选择模式
  - [x] 选中后可执行多种操作（翻译/配置工具/删除）
  - [x] 退出批量模式清空选择
- **关联文件**：`src/pages/Skills.tsx`

### S-03 🔴 卡片点击直接打开编辑器，易误触

- **现象**：Skill 卡片点击即打开编辑器，没有"查看详情"和"编辑"的区分。
- **影响**：用户只是想看看内容却被拉进编辑器；误触率高，尤其在批量选择时。
- **改进建议**：卡片点击展开详情/预览，明确提供"编辑"按钮才进入编辑器；批量模式下点击应进入选择而非打开编辑器。
- **验收标准**：
  - [x] 卡片点击不再直接进入编辑器
  - [x] 提供"编辑"按钮明确入口
  - [x] 批量模式下点击卡片只切换选中状态
  - [x] 非批量模式下点击卡片可展开详情预览
- **关联文件**：`src/pages/Skills.tsx`

### S-04 🟢 作用域过滤术语不直观

- **现象**：作用域切换标签为 all/global/project，对新用户是术语。
- **影响**：用户不理解 global 和 project 的区别，不知道当前看到的是哪些 Skills。
- **改进建议**：用更直白的标签，如"全部 / 全局 / 当前项目"，并在 project 旁显示当前项目名。
- **验收标准**：
  - [x] 标签改为"全部 / 全局 / 当前项目"
  - [x] "当前项目"旁显示项目名
  - [x] 切换时有简短说明 tooltip
- **关联文件**：`src/pages/Skills.tsx`

### S-05 🟢 CreateSkillDialog 字段过少

- **现象**：创建 Skill 只有 name（自动转 ID）+ description 两个字段。
- **影响**：用户创建后还要去编辑器手动写 frontmatter、选工具，流程割裂。
- **改进建议**：创建时可选填目标工具、标签，自动生成带 frontmatter 的初始文件。
- **验收标准**：
  - [x] 创建对话框可选填目标工具
  - [x] 创建对话框可选填标签
  - [x] 生成的 SKILL.md 包含 frontmatter
- **关联文件**：`src/pages/Skills.tsx`

## 模块三：Tools 管理页面

- **关联文件**：`src/pages/Tools.tsx`

## 模块四：Marketplace 市场

### M-01 🟡 描述异步加载导致闪烁

- **现象**：[Marketplace.tsx](file:///Users/yjw/code/projects/skills-manager/src/pages/Marketplace.tsx) 描述按批次加载（DESCRIPTION_BATCH_SIZE=12），加载前后卡片高度跳变。
- **影响**：列表抖动严重影响阅读体验，用户视线被打断。
- **改进建议**：卡片预留固定高度骨架屏；或列表先加载描述再渲染，避免高度跳变。
- **验收标准**：
  - [ ] 描述加载期间卡片高度不变
  - [ ] 无视觉抖动
  - [ ] 骨架屏占位
- **关联文件**：`src/pages/Marketplace.tsx`

### M-02 🟢 无排序选项

- **现象**：市场列表无排序（按更新时间/星标/名称等）。
- **影响**：用户找不到热门或最新的技能，只能按默认顺序翻。
- **改进建议**：提供"最新 / 最热 / 名称"排序切换。
- **验收标准**：
  - [ ] 提供至少 3 种排序方式
  - [ ] 排序状态可记忆
- **关联文件**：`src/pages/Marketplace.tsx`

### M-03 🟡 安装后无引导跳转

- **现象**：安装完技能后停留在市场页，只提示"安装成功"。
- **影响**：用户不知道去哪查看/编辑刚装的技能，可能重复安装。
- **改进建议**：安装成功提示中提供"去查看"按钮，跳转到 Skills 页并高亮新装的技能。
- **验收标准**：
  - [ ] 安装成功 Toast 含"去查看"按钮
  - [ ] 点击跳转 Skills 页
  - [ ] 新装技能高亮显示
- **关联文件**：`src/pages/Marketplace.tsx`

### M-04 🟡 无卸载入口

- **现象**：市场页只有安装/更新，卸载要去 Skills 页。
- **影响**：用户在市场看到不想要的技能，无法直接卸载，操作路径长。
- **改进建议**：已安装的技能在市场页显示"已安装/卸载"状态和操作。
- **验收标准**：
  - [ ] 已安装技能显示"已安装"状态
  - [ ] 提供卸载按钮
  - [ ] 卸载有二次确认
- **关联文件**：`src/pages/Marketplace.tsx`

### M-05 🟢 无限滚动无"回到顶部"

- **现象**：无限滚动加载更多，但无快速回到顶部按钮。
- **影响**：翻了很多页后想回顶部搜索/筛选很麻烦。
- **改进建议**：滚动超过一屏后显示"回到顶部"浮动按钮。
- **验收标准**：
  - [ ] 滚动超过一屏显示回顶按钮
  - [ ] 点击平滑滚动到顶部
- **关联文件**：`src/pages/Marketplace.tsx`

## 模块五：Settings 设置

### SE-01 🟡 GitHub Token 无显示切换

- **现象**：[Settings.tsx](file:///Users/yjw/code/projects/skills-manager/src/pages/Settings.tsx) LLM 配置有 API Key 显示切换，但 GitHub Token 没有。
- **影响**：用户填错 Token 无法核对，体验不一致。
- **改进建议**：所有敏感字段统一提供"显示/隐藏"切换。
- **验收标准**：
  - [ ] GitHub Token 字段有显示/隐藏切换
  - [ ] 所有敏感字段（Token/Key）行为一致
- **关联文件**：`src/pages/Settings.tsx`

### SE-02 🟢 账户部分内容稀疏

- **现象**：cloud sync 已移除，但账户入口仍保留，点进去内容空旷。
- **影响**：用户点进账户页发现没什么内容，产生困惑。
- **改进建议**：要么移除账户入口，要么明确标注"账户功能即将上线"，避免空状态。
- **验收标准**：
  - [ ] 账户页有空状态说明或移除入口
  - [ ] 不出现空旷无内容的页面
- **关联文件**：`src/pages/Settings.tsx`

### SE-03 🟢 无重置配置选项

- **现象**：设置无"恢复默认"或"重置所有配置"选项。
- **影响**：用户配置乱了之后无法一键恢复，只能逐项改回或重装。
- **改进建议**：提供"恢复默认设置"按钮，带二次确认。
- **验收标准**：
  - [ ] 提供"恢复默认"按钮
  - [ ] 操作有二次确认

## 风险与回滚

### 风险评估

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| Skills 头部重组破坏现有用户习惯 | 中 | 中 | 保留所有功能，仅调整层级；灰度观察 |
| 卡片点击行为改变影响老用户 | 中 | 中 | 提供"进入编辑"按钮，保证可达性 |
| 全局搜索增加包体积 | 低 | 低 | 懒加载搜索组件 |
| Editor 文件操作有数据丢失风险 | 中 | 高 | 删除二次确认 + 回收站机制 |
| 中英统一遗漏文案 | 高 | 低 | 全量 i18n key 扫描 + 人工抽检 |

### 回滚原则

- 每个阶段独立可回滚，不影响其他阶段
- 涉及用户数据的操作（删除/重命名）必须有确认和撤销路径
- 头部重组和卡片行为变更保留旧入口至少一个版本，便于过渡
