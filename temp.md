  软链接策略的选择

  方案: A. 目录级软链接

  优点: 最简单，一次配置                                                                                    
  缺点: 工具可能不支持；无法单独禁用 skill                                                                  
  ────────────────────────────────────────                                                                  
  方案: B. 文件级软链接                                                                                     
  说明: 每个 skill 单独创建软链接                                                                           
  优点: 可精细控制启用/禁用                                                                                 
  缺点: 链接数量多，管理复杂

  方案: C. 公共目录 + 配置覆盖                                                                              
  说明: 公共目录存 skills，修改各工具的配置文件让其读取公共目录

  缺点: 需要各工具支持自定义路径

  首次导入的逻辑：                                                                                          
  1. 扫描已检测工具的 skills 目录                                                                           
  2. 把发现的 skills 移动（不是复制）到公共目录                                                             
  3. 在原位置创建软链接指向公共目录                                                                         
  4. 多个工具有相同 skill 时，保留最新版本，去重合并                                                        
                                                                                                            
  后续用户直接在工具目录安装 skill 的处理：                                                                 
                                                                                                            
  有几种策略：

  策略: B. 自动收编                                                                                         
  说明: 检测到后自动移动到公共目录并创建软链接                                                              
  ────────────────────────────────────────                                                                  
  策略: C. 忽略                                                                                             
  说明: 不管它，让它独立存在于那个工具目录下                                                                
  我的建议是 A（定期检测 + 提示收编）：                                                                     
  - 尊重用户操作，不自动改动文件
